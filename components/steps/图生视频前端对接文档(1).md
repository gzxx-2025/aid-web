# 图生视频（漫剧版）前端对接文档

> 适用范围：分镜「图生方向」视频提示词生成 + 图生视频出片。
> 与既有「多参方向」（`video_prompt`）物理隔离，本方向统一使用新列 `aid_storyboard.video_prompt_image`。
> 任务 / 进度 / 取消 / 计费 / 退款 / 排队全部复用系统既有机制，前端订阅方式与多参方向一致。

---

## 0. 名词与前置

| 概念 | 说明 |
|---|---|
| 业务分类 | 图生方向提示词智能体 `biz_category_code = main_storyboard_video_prompt_image`，默认 `agent_code = aid_visual_director_image` |
| 提示词存储列 | `aid_storyboard.video_prompt_image`（图生方向专用；多参方向用 `video_prompt`，互不影响） |
| 出片模型池 | `aid_ai_model_func_config.func_code = main_storyboard_video_image`（图生出片**专用**池，`model_type=video`，仅放支持图片输入的视频模型） |
| 提示词模型池 | `aid_ai_model_func_config.func_code = main_storyboard_video_prompt_image`（`model_type=text`；后端强校验，所选文本模型必须在此池内） |

通用返回结构（与全站一致）：

```json
{ "code": 200, "msg": "操作成功", "data": { } }
```

- 业务异常：`code != 200`，`msg` 为简短中文文案（如「请先生成提示词」「图片超出上限」），前端直接弹出 `msg`。

---

## 1. 批量生成「图生视频提示词」

把分镜画面生图提示词 + 分镜脚本 + 角色形态设定 + 全局风格，经「视觉导演（漫剧版）」智能体整段批量生成图生视频提示词，写回 `aid_storyboard.video_prompt_image`。异步父任务，前端用现有 SSE / 任务查询订阅进度。

- **URL**：`POST /api/user/storyboard/generate/video-prompt-image`
- **鉴权**：需登录态（同其他 C 端接口）

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `projectId` | Long | 是 | 项目 ID |
| `episodeId` | Long | 是 | 剧集 ID（电影项目固定传 0） |
| `storyboardIds` | Long[] | 否 | 目标分镜 ID 列表。**不传/空 → 处理本剧集全部分镜**（由 `overwrite` 区分重新/继续生成）；**传了 → 仅处理这些且默认覆盖（重新生成）**。任一不属于该 项目+剧集+用户 整批拒绝 |
| `agentCode` | String | 否 | 智能体编码；默认 `aid_visual_director_image`；后端强校验 `biz_category_code=main_storyboard_video_prompt_image`，否则报「智能体不可用」 |
| `modelCode` | String | 否 | 文本模型编码；优先级：入参 → 智能体默认 `model_code` → **`main_storyboard_video_prompt_image` 池内第一个**（即"只配池也能跑"）。最终模型必须 `model_type=text` 且在该池内 |
| `overwrite` | Boolean | 否 | **仅在不传 storyboardIds（全集）时生效**：`false`=继续生成（跳过已有 `video_prompt_image` 的镜头，仅补未生成；全部已生成则报「视频提示词已生成」）；`true`=重新生成（全部覆盖）。传了 storyboardIds 时一律按覆盖处理 |

请求示例：

```json
{
  "projectId": 1001,
  "episodeId": 0,
  "storyboardIds": [20001, 20002],
  "modelCode": null,
  "overwrite": true
}
```

### 响应体（`data`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `taskId` | Long | 父任务 ID，用于订阅进度 / 取消 |
| `status` | String | 固定 `PENDING` |
| `totalShots` | Integer | 本次处理的分镜数 |

```json
{ "code": 200, "msg": "操作成功", "data": { "taskId": 80001, "status": "PENDING", "totalShots": 2 } }
```

### 前置校验与错误文案

| 文案 | 触发条件 |
|---|---|
| `智能体不可用` | 智能体停用 / 业务分类不匹配 / **prompt_content 未配置**（漫剧版提示词需先在后台补好） |
| `未配置模型` / `模型不可用` | 模型缺失或非文本模型 |
| `功能可选模型未配置` / `模型不在该业务可选范围内` | `main_storyboard_video_prompt_image` 池未配置 model_ids，或所选文本模型不在池内 |
| `请先生成分镜` | 目标镜头无 `script_params` |
| `缺少画面描述` / `缺少参考信息` | `script_params` 缺关键字段 |
| `请先生成分镜图脚本` | 目标镜头无 `image_prompt`（漫剧版强依赖生图提示词提取形态名） |
| `视频提示词已生成` | 继续生成模式下全部已生成 |
| `任务处理中` | 同项目+剧集已有进行中的视频提示词任务 |

### 续生（部分失败后补跑）

- **URL**：`POST /api/user/storyboard/generate/video-prompt/resume`（与多参方向共用，按 `taskId` 自动识别方向）
- 请求体：`{ "taskId": 80001 }`
- 仅 `PARTIAL_FAILED` 终态、且计费已结算的任务可续生；只重跑未生成镜头。

## 2. 图生视频出片（前端直传图片）

由前端直传参考图片 +（可选）提示词，调用图生视频模型异步出片。

- **URL**：`POST /api/user/storyboard/generate/video/image`
- **鉴权**：需登录态

### 提示词来源优先级

1. 入参 `videoPrompt` 不为空 → 用它；并在**建任务前**直接落库到 `aid_storyboard.video_prompt_image`（不依赖出片成功）。
2. 入参为空 → 回落读库 `aid_storyboard.video_prompt_image`。
3. 两者皆空 → 报错 `请先生成提示词`（请先调用第 1 节生成，或本次传入 `videoPrompt`）。

> 设计说明：第 1 步「点了生成即落库」是有意为之，便于失败重试与前端回显，与出片成败解耦。

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `storyboardId` | Long | 是 | 分镜 ID |
| `images` | String[] | 是 | 前端直传参考图片 URL 列表，**至少 1 张**；张数上限 = 模型 `capability_json.maxReferenceImages`（超出报「图片超出上限」）。第 1 张在未指定首帧时兜底作首帧 |
| `videoPrompt` | String | 否 | 图生视频提示词；为空回落 `video_prompt_image` |
| `modelName` | String | 否 | 视频模型编码；为空取 `main_storyboard_video_image` 池内第一个；必须 `model_type=video`、**支持图片输入**且落在该图生出片专用池内 |
| `baseImageRecordId` | Long | 否 | 首帧来源 `aid_gen_record.id`；**仅在显式传入时**作为首帧覆盖。不传则由系统从 `images` 选首帧（单首帧模型取第 1 张），**不再回落分镜 `final_image_id`** |
| `aspectRatio` | String | 否 | 宽高比（如 16:9 / 9:16 / 1:1）；为空按模型默认（仅模型支持时生效） |
| `durationSeconds` | Integer | 否 | 时长（秒）；为空按模型默认（仅模型支持时生效） |
| `count` | Integer | 否 | 生成数量，默认 1，范围 [1,4]；每条独立计费 / 落一行 `aid_gen_record` |
| `generateAudio` | Boolean | 否 | 是否生成音频（仅部分模型支持） |
| `userInputText` | String | 否 | 用户补充文本，最大 500 字符（超出截断），拼接到提示词后，前缀「用户补充：」 |

> **多图如何被使用（按模型自动适配）**：后端把 `images` 交给统一的视频参考装配层按厂商适配——
> 支持多图参考的模型（如 HappyHorse）会用上多张并自动补「参考图说明」段；仅支持单首帧的模型
> （如即梦/万相等）会自动只用第 1 张作首帧，多余图不会硬塞给上游。因此「最终用几张」以所选模型能力为准。

请求示例：

```json
{
  "storyboardId": 20001,
  "images": [
    "https://oss.example.com/aid/ref/a.png",
    "https://oss.example.com/aid/ref/b.png"
  ],
  "videoPrompt": "镜头运动：推镜头，缓慢推进至半身。\n画面描述：……",
  "modelName": null,
  "aspectRatio": "16:9",
  "durationSeconds": 5,
  "count": 1,
  "generateAudio": false,
  "userInputText": "运镜再慢一点"
}
```

### 响应体（`data`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `taskId` | Long | 父任务 ID |
| `status` | String | 固定 `PENDING` |
| `storyboardId` | Long | 分镜 ID |
| `modelName` | String | 实际使用的视频模型编码 |
| `count` | Integer | 出片数量 |

```json
{ "code": 200, "msg": "提交成功", "data": { "taskId": 80010, "status": "PENDING", "storyboardId": 20001, "modelName": "xxx-video", "count": 1 } }
```

### 错误文案

| 文案 | 触发条件 |
|---|---|
| `请上传图片` | `images` 为空 / 全为空串 |
| `图片无效` | 某张图片 URL 格式非法、不可访问或不是图片（后端逐张强校验） |
| `图片超出上限` | 图片数 > 模型 `maxReferenceImages` |
| `该模型不支持图片` | 模型 `supports_image_input` 非真，或 `maxReferenceImages=0`（禁用参考图） |
| `该模型不支持多图` | 传入多张图但模型 `supports_multi_image_input=false` |
| `请先生成提示词` | 入参与库 `video_prompt_image` 均为空 |
| `提示词过长` | 入参 / 库回落 / 拼接用户补充后的最终提示词超长 |
| `功能未配置` / `模型不在该业务可选范围内` | `main_storyboard_video_image` 池未配置，或所选模型不在池内 |
| `模型不存在` / `模型不可用` | 模型校验不通过 |
| `时长无效` | `durationSeconds <= 0` |
| `底图无效` / `无权访问` / `底图未就绪` | `baseImageRecordId` 校验不通过 |
| `任务处理中` | 同一分镜已有进行中的出片任务 |

## 3. 进度订阅 / 取消（与既有一致，无需新增）

两个接口均返回 `taskId + PENDING`，前端用系统现有机制订阅与取消：

| 用途 | 接口 |
|---|---|
| SSE 实时进度 | `GET /api/user/task/stream/{taskId}` |
| 取消任务 | `POST /api/user/asset/extract/cancel` |

- SSE 事件含 `init / progress / partial_failed / complete / error / cancelled` 等，前端按现有逻辑处理即可。
- 出片完成后，结果落 `aid_gen_record`（`gen_type=i2v`），前端按现有「分镜出片结果」查询方式拉取。

## 4. 推荐前端调用流程

```
（一次性，后台）① 为 aid_visual_director_image 补好漫剧版提示词；
              ② 配置 main_storyboard_video_prompt_image 池（文本模型；接口未传 modelCode 时取池内第一个）；
              ③ main_storyboard_video_image 池已由 SQL 播种当前支持图片输入的视频模型（含 HappyHorse），可按需增删
      │
1. 选中分镜 → POST /generate/video-prompt-image  → 拿 taskId
      │  （SSE 订阅至 complete；video_prompt_image 已回填）
2. 进入出片页：上传/选择参考图片 → POST /generate/video/image
      │     - 不传 videoPrompt：用库里 video_prompt_image
      │     - 传 videoPrompt：本次用它，并自动落库 video_prompt_image
      │  （SSE 订阅至 complete）
3. 拉取 aid_gen_record 展示视频结果
```

> 也支持「跳过第 1 步」：前端直接在第 2 步传 `videoPrompt` 出片，系统会把该提示词落库。
