# 现有代码安全整改方案（不影响现有逻辑）

> 适用项目：aid-pc（Nuxt 3 视频生成创作流程）  
> 硬约束：**整改不得改变任何现有业务行为**（接口调用、时序、状态机、文案、样式视觉可接受「像素级一致」）  
> 配套规范：`docs/2026-07-22-frontend-development-standards.md`  
> 更新日期：2026-07-22

---

## 1. 目标与非目标

### 1.1 目标

1. **降体积**：把上万行巨石文件拆成可维护模块。  
2. **去重复**：多处高度相似的逻辑/样式收敛为单一实现。  
3. **降维护成本**：后人改一处即可，而不是改 10 处。  
4. **全程行为等价**：用户无感；测试与手工验收通过。

### 1.2 非目标（本阶段不做）

- 不重做产品交互、不换 UI 框架、不改接口协议。  
- 不借整改「顺便优化」业务规则（除非单独开需求且有验收）。  
- 不做一次性全仓库大重构；避免超大 PR。  
- 不删除仍被引用的「看起来多余」代码，除非有静态证明 + 运行验证。

---

## 2. 安全原则（必须遵守）

| 原则 | 含义 |
|------|------|
| **行为冻结** | 抽离前后：请求参数、SSE 订阅、成功/失败/取消路径、store 写入字段完全一致 |
| **先搬后删** | 先把函数原样挪到新文件并 re-export，确认引用切换成功，再删旧位置 |
| **小步提交** | 每个 PR 只做一类事（如「仅搬移纯函数」或「仅抽共享 CSS」） |
| **可回滚** | 每个阶段可独立回滚；禁止「拆文件 + 改逻辑 + 改样式」捆在同一提交 |
| **对照验收** | 每阶段有固定手工用例 + 能单测的补单测 |
| **视觉等价** | 样式整改以截图/并排对比为准；变量替换必须同色同值 |

**允许的改动**：文件路径、函数位置、import 路径、等价命名（需保留旧名导出一段时间）。  
**禁止的改动**：条件判断、默认值、错误文案、任务状态流转、接口字段、事件时序。

---

## 3. 整改策略总览（推荐路径）

采用 **「绞杀者（Strangler）」+「搬家式重构」**：

```text
阶段 0 基线与清单
  → 阶段 1 纯函数/门闸抽离（零行为风险）
  → 阶段 2 重复样式收敛到 shared CSS（视觉对齐）
  → 阶段 3 组件内区块拆子组件（props 透传，逻辑不动）
  → 阶段 4 composable 按职责拆文件（对外 API 保持）
  → 阶段 5 相似弹窗/步骤去重（抽出共用内核，外壳仍独立）
  → 阶段 6 持续治理（门槛门禁 + 新代码只增不胀）
```

**优先级排序规则**

1. 收益高且风险低（纯 utils、重复 CSS 变量）先做。  
2. 业务最敏感（SSE、批量生成、作品切换恢复）后做、步子更小。  
3. 行数最大但不常改的文件，可排在「常改又重复」的文件之后。

## 5. 分阶段实施方案

### 阶段 0：基线冻结（0.5–1 天）

**做什么**

1. 列出本迭代要动的文件清单与「行为对照用例」（见第 7 节模板）。  
2. 对纯逻辑补/补齐 `*.test.mjs`（已有测试风格可复用）。  
3. 关键关键路径截图基线（第三步、分镜、编辑弹窗打开态、批量生成中、刷新恢复）。  
4. 约定：整改分支命名 `refactor/safe-<scope>`，每个 PR 描述写明「无行为变更」。

**完成标准**：有清单、有基线截图/用例、有回滚方式（revert PR）。

---

### 阶段 1：纯搬家抽离（最低风险，优先做）

**适合对象**

- `utils` 内可独立的纯函数（门闸、映射、格式化、结果解析）。  
- 组件/`composables` 里已是纯函数但挤在大文件中的片段。

**步骤（固定套路）**

1. **原样剪切**函数到新文件（不改一行逻辑）。  
2. 旧文件 `export { xxx } from './newFile'` **或** 改 import 指向新文件（二选一，全仓库统一）。  
3. 跑相关 `*.test.mjs` + 手工点路径。  
4. 确认无循环依赖后，删除旧实现。

**示例落点**

- 批量恢复门闸、任务类型判断、panel UI 应用函数 → `utils/`  
- `businessApi.ts` 按 `project` / `storyboard` / `asset` / `auth` 拆文件，保留 `businessApi.ts` 作为 barrel 导出

**禁止**：搬家同时「顺手重构参数」「合并 if」「改名且不保留别名」。

**完成标准**：行数下降，对外 import 路径兼容或已全局替换且行为不变。

---

### 阶段 2：样式安全收敛

**策略**

1. **先变量对齐**：把多处相同的 hex/px 提成已有 CSS 变量（值必须一致）。  
2. **再 class 合并**：两个组件 scoped 中大段相同规则 → 迁入 `*-shared.css`，组件根节点增加约定 class（如已有 `storyboard-step`、`create-step-scp`）。  
3. **后删 scoped 重复**：确认视觉一致再删组件内重复规则。

**安全手法**

- 一次只迁移一个视觉区块（如「顶栏按钮」或「列表行高」）。  
- 用开发者工具对比 computed style（颜色、字号、间距）。  
- Ant Design 覆盖仍集中在 `create-steps-ant-overrides.css`，不把 `!important` 散回组件。

**优先文件**

- `SceneCharacterProp.vue` 内与 `scp-step-shared.css` 重复的部分  
- 分镜三步（脚本/视频/配音）与 `storyboard-step-shared.css` 的差异收口  
- 多个 Edit*Modal 的弹窗壳、工具条、媒体区公共样式 → 新建 `edit-media-modal-shared.css`（仅在确认三处高度同构后）

**完成标准**：scoped 行数明显下降；抽样页面视觉与基线一致。

---

### 阶段 3：组件「切块」拆分（逻辑仍在父级或原 composable）

**策略：只拆模板，先不改数据流**

1. 把大模板中独立 UI 块切成子组件。  
2. 第一轮用 **大量 props + emits** 或临时 `v-bind="$attrs"`，**业务函数仍留在父组件**。  
3. 验证通过后，第二轮再把「仅子树使用的 state」下移（仍不改算法）。

**SceneCharacterProp.vue 建议切块顺序**

1. 顶栏 / Tab  
2. 列表与卡片区（场景/角色/道具可先共用壳）  
3. 各业务弹窗改为异步子组件或独立文件引用（已是 Modal 的保持行为）  
4. 批量生成入口与进度展示

**StoryboardScript.vue 等**

- 工具条、列表面板、生成侧栏/弹窗壳分离

**完成标准**：父文件行数下降；交互路径与拆前一致（含 loading、禁用态）。

---

### 阶段 4：Composable 按职责拆文件（保持导出 API）

**以 `useStoryboardVideoBatchGenerate.ts` 为样板，其它 Batch 仿做**

建议物理拆分（名称可微调，但 **对外 `useXxx()` 签名不变**）：

| 新文件职责 | 内容 |
|------------|------|
| `*Follow.ts` | SSE/任务跟随、Set 登记 |
| `*Restore.ts` | 刷新/回页立即恢复 loading |
| `*ApplyResult.ts` | 写回 panel / store |
| `*RunBatch.ts` | 发起批量请求 |
| `useXxx.ts` | 组装导出，保持原 API |

**安全手法**

1. 先拆文件，`useXxx.ts` 继续导出相同函数名。  
2. 全仓库 grep 旧路径，确保无遗漏。  
3. 重点回归：批量进行中切作品、刷新、关弹窗再开、失败回滚。

**完成标准**：单文件 <500 行目标逼近；外部调用方零改或仅改 import。

---

### 阶段 5：跨文件去重（相似实现合并）——最谨慎

**典型对象**

- `EditSceneImageModal` / `EditStoryboardImageModal` / `EditStoryboardVideoModal`  
- `useStoryboardImageBatchGenerate` / `Video` / `Audio` / `Script` 中的恢复与 follow 模式  
- 首页作品库/资产库列表若存在平行复制

**推荐做法：提取「内核」而不是强行合成一个超级组件**

```text
useEditMediaTaskCore.ts   ← 提交/跟随/取消/写回（参数化差异）
EditMediaModalShell.vue   ← 壳布局（slots 填差异区）
各 EditXxxModal.vue       ← 只保留差异：字段、文案、接口参数拼装
```

**合并判定清单（全部满足才合并）**

- [ ] 控制流相似度高（成功/失败/取消节点一致）  
- [ ] 差异可参数化（taskType、写回字段、UI slot）  
- [ ] 有自动化测试或可脚本化对照  
- [ ] 先做 1 个弹窗试点，再推广

**禁止**：为了去重而改变某一弹窗独有的边界行为。

---

### 阶段 6：制度化，防止回潮

1. 把《前端开发规范》中的体量门槛纳入 Code Review 必检项。  
2. 可选：CI 增加「文件行数警告」（超标仅 warn，不立刻 fail，避免堵死业务）。  
3. 新功能：**先抽再写**；禁止在 P0 巨石文件上直接 +500 行。  
4. 每双周选 1 个超标文件做「安全微拆」（固定时间盒，避免无限重构）。

## 6. 风险分级与应对

| 风险级 | 场景 | 应对 |
|--------|------|------|
| 低 | 纯函数搬家、barrel 导出 | 单测 + 类型检查 |
| 中 | CSS shared 化 | 截图对比 + 创作页/首页分壳检查 |
| 中高 | 拆子组件 | 聚焦事件冒泡、v-if 时序、ref 调用 |
| 高 | SSE/批量/恢复合并 | 分 PR；保留旧函数别名；用例必须含切作品与刷新 |
| 极高 | store 大拆 | 仅外置纯函数；不改 state 形状；持久化字段不动 |

**出现行为差异时**：立即回滚该 PR，用「对照用例」定位；禁止在错误结果上继续叠加整改。

## 7. 每阶段验收用例模板（可复制）

### 7.1 通用

1. 登录 → 打开已有作品 → 进入对应步骤。  
2. 重复整改前的同一操作 2 次，对比网络请求 payload 与 UI 结果。  
3. 生成中：切换到其它作品再切回；刷新页面；关闭弹窗再打开。  
4. 失败态：断网/接口错误提示是否与改前一致。  
5. 取消任务：按钮禁用态与结果是否与改前一致。

### 7.2 第三步（SceneCharacterProp）

- Tab 切换、卡片选中、单张生成、批量生成、编辑图片弹窗、导入资产。

### 7.3 分镜步骤

- 脚本批量、图片批量、视频批量、恢复 loading、历史记录卡。

### 7.4 样式

- 顶栏按钮、列表行高、空状态、弹窗深色主题是否与基线截图一致。

## 9. PR 规范（整改专用）

**标题示例**

- `refactor(safe): 搬移 storyboard image restore gate 至独立 utils`  
- `refactor(safe): 将 SCP 顶栏重复样式迁入 scp-step-shared`  
- `refactor(safe): 拆分 SceneCharacterProp 顶栏为子组件（无逻辑变更）`

**正文必须包含**

1. 行为变更：**无**（或明确列出，若有则本方案不允许合并）  
2. 搬移/拆分对照表（旧路径 → 新路径）  
3. 验收用例执行结果  
4. 截图（涉及样式时）

**单 PR 限制**

- 不混合功能需求与整改。  
- 建议 diff 触及文件 <15 个，或行变更以「搬家」为主。

## 10. 成功指标（3 个月后可复盘）

| 指标 | 现状参考 | 目标 |
|------|----------|------|
| >5000 行 Vue 文件数 | 4+ | 0 |
| >3000 行 Vue 文件数 | 若干 | ≤1（或有明确拆分中） |
| 同构编辑弹窗重复实现 | 3–4 套平行代码 | 1 套内核 + N 个薄外壳 |
| 步骤样式 | 多处 scoped 重复 | 主路径走 shared + 变量 |
| 因整改导致的缺陷 | — | 0 起「逻辑回归」级线上问题 |

---

## 11. 执行口诀

1. **先测后搬，先搬后删。**  
2. **一次一类，可随时回滚。**  
3. **对外 API 先稳定，内部结构再变瘦。**  
4. **去重提取内核，不吞掉差异行为。**  
5. **新功能遵守开发规范，整改才不会白做。**
